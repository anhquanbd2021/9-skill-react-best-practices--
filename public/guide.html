Guide

What a "React best practices" skill mechanically is, how this lab makes it runnable, and where the model stops being true.

The contract: checklist lines activate detectors

A skill file has frontmatter (name, description) and a body. This lab treats the body as a contract: each checklist line shaped like - `rule-id` activates the detector of the same id in public/rules.mjs. A skill whose body is prose — like examples/react-101/SKILL.md ("Helps with React.") — parses fine and activates zero rules. It produces the same scan as no skill at all, which is exactly the failure the article describes: advice that can't be executed can't catch anything.

The five rules

Rule idWhat it catchesRender cost in the simulator
unstable-keyList keyed by index (or missing key).On a reorder tick, every row re-renders instead of the moved one.
unstable-propInline object/array/function prop passed to a memoized child.The child's memo never skips — it re-renders every parent render.
effect-depsEffect reads a value missing from its dep array.None in the sim — this is a correctness finding (stale closure), proving the checklist isn't only about render counts.
derived-stateuseState holding a value computable during render.+1 render pass per entry each time the component renders (render → effect → setState → render again).
unstable-contextProvider value built inline each render.Every consumer in the subtree re-renders on every provider render — memo or not.

The render simulator

Each tick, the root's state changes and it renders. A child re-renders when: it's not memoized; a prop is an inline literal (new reference); it's a reorder tick and a prop reference changed; or it consumes a context whose provider emitted an inline value. checkout seeds all five anti-patterns; checkout-fixed is the same topology with the checklist applied. Run npm run report for the side-by-side: 68 renders vs. 14 — the ~80% the source post advertises, shown as a consequence of the checklist rather than a promise.

The honest edge

clean-but-broken scans clean under the full skill — and carries a duplicated source of truth (its designNote). Zero findings, real bug. A render checklist reviews patterns; it does not review whether the design was right. Reviewer-bot, not architect.

Honest limits

  • Component trees are JSON descriptors, not JSX — detection is by declared attributes, not AST analysis. A real review skill operates on code text with all its ambiguity.
  • The simulator encodes simplified propagation rules, not React internals — no batching, no transitions, no concurrent scheduling.
  • The 80% figure is fixture-specific by design: it demonstrates that "fewer renders" is measurable, not that every codebase contains it.
  • effect-deps is counted as a finding but costs no renders in the sim — real stale closures cost correctness, which is worse.
